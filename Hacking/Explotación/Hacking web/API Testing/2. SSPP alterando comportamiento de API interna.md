Lo mas probable es que el usuario que se envía esté siendo usando internamente en una API, tal como se ve en el siguiente grafico, y no conocemos que otros parámetros se pasan a la API o si tan siquiera existen mas parámetros para la API interna:


![[Pasted image 20250827233826.png]]


Lo que podemos hacer es revisar si podemos envenenar le parámetro de usuario (parameter pollution), para esto podemos enviar el siguiente payload:

```java
CSRF=....&username=administrator%26test%3dhola
```

Si URL-decodeamos esto nos da como resultado:

```java
CSRF=....&username=administrator&test=hola
```

Pero lo encodeamos para que cuando lo pasemos al backend no lo confunda como un parametro mas, por ende, cuando el backend lo decodé, y lo envié a la API sea como un parametro mas, de tal forma que quedará así


```java
username=administrator&test=hola // ?? no sabemos que hay despues ?? 
```
