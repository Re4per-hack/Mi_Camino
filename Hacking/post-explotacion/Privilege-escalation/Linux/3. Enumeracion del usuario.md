# ==Archivos SUID== 

Podemos ver los archivos SUID para nuestro usuario usando el siguiente comando:

```shell
find / -perm -4000 -user root  2>/dev/null
```

# ==Grupos==

### Ver grupos del usuario actual

Para ver los grupos a los que pertenece el usuario actual podemos usar el comando:

``` ruby
groups
```

Alternativamente podemos usar:

```ruby
id
```
### Ver grupos de un usuario especifico

Para ver los grupos de un usuario que no sea el actual podemos usar el siguiente comando:

```ruby
groups {USUARIO}
```
# ==sudo -l== 

### Lectura de sudo -l 

```shell 

$> sudo -l 

Matching Defaults entries for jp on parrot:
env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin :/usr/sbin\ :/usr/bin\:/sbin\:/bin, use_pty

User jp may run the following commands on parrot:
(ALL : ALL) ALL
(ALL) ALL

```

- ***(ALL : ALL) ALL***

El primer `ALL` → significa que puede ejecutar comandos como **cualquier usuario**.
El segundo `ALL` → significa que puede ejecutar comandos como **cualquier grupo**.
El último `ALL` → significa que puede ejecutar **cualquier comando**.

- ***(ALL) ALL***

Esta es otra forma de escribirlo (dependiendo de la versión de `sudo`).  
Significa lo mismo: **puede ejecutar cualquier comando como cualquier usuario**.

### Ejecutables con sudo

Hay varios ejecutables del sistema de los cuales si tenemos permisos con sudo podemos aprovecharnos, para ver que podemos hacer con cada uno de estos ejecutables en caso de tener la opcion de usar sudo, podemos revisar la siguiente pagina [CTFOBins](https://gtfobins.github.io/)
Para listar los ejecutables que podemos usar con sudo podemos usar el siguiente comando:

```shell
sudo -l 
```


# ==sudoers defaults entries / Matching Defaults entries:==

 Son las políticas generales que se aplican a tu usuario al usar sudo, definidas en el archivo /etc/sudoers o en algún archivo dentro de /etc/sudoers.d/.

![[Pasted image 20250915190712.png]]

### env_reset / !env_reset

Cuando aparece env_reset significa que al ejecutar comandos con sudo, elimina la mayoría de variables de entorno y deja solo un conjunto seguro (ej. HOME, LOGNAME, SHELL, USER, etc.).

Si esta opcion tiene el signo "!" antes del nombre (!env_reset) significa que no va a eliminar o limpiar ninguna variable de entorno.

Si el signo "!" está puesto antes del nombre debemos fijarnos si hay algujna aplicacion que podamos ejecutar como sudo , esto nos permitiría que como no se eliminan  las variables de entorno que tengamos, alguna aplicación use una de estas para alguna configuración o comandos.
### env_delete 

Define que se eliminen ciertas variables de entorno, en este caso PATH. 

Te preguntarás que PATH se va a usar para ejecutar los comandos, y la respuesta es la siguiente configuración.

### secure_path

Esta configuración define el PATH que se va a usar en vez del PATH del usuario.


### mail_badpass

Esta configuración define que si se usa la contraseña incorrecta con sudo, va a enviar un mail avisando al administrador a /var/mail/root o /var/mail.

### use_pty

Esta configuración define que se use una pseudo-terminal, (PTY) lo cual le puede permitir a sudo registrar y vigilar las acciones que se hacen.
